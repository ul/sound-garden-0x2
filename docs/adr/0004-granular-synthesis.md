# Granular synthesis: trigger-fired grains over tables or a live buffer

Granular synthesis is two ops over one grain engine: `grain:NAME:N` reads a table (recorded with `wt:`, loaded with `ft:`, or an audio file path loaded on first use) and `granulate:SECONDS:N` reads a rolling buffer of its own input. Both source kinds were wanted: tables cover files and phrases recorded earlier in the program, while the live buffer processes whatever is flowing through the program right now, which a one-shot `wt:` recording cannot do.

Grains are fired by a trigger input, not by an internal density parameter: `<position> <duration> <rate> <trig> grain:NAME:N` and `<x> <back> <duration> <rate> <trig> granulate:SECONDS:N`. Density was rejected because it hides the grain clock inside the op, while a trigger input composes with everything the language already has — `metro` for clouds, `trig:` patterns for rhythmic grains, `chance` to thin them, `rnd`/`sh` for per-grain parameters — the same signal-native reasoning as patterns (ADR 0001). A rising edge on any channel starts one grain; like `poly`, the op latches parameters at that moment instead of streaming them, so each grain keeps the position, duration and rate it was born with. Parameters are latched per channel, so stereo inputs (e.g. a little `noise` on the position) give each channel its own read point without a pan parameter. The trigger amplitude is latched as the grain's gain, matching how `impulse` and `poly` treat trigger amplitude.

A grain plays `duration` seconds of source at `rate` frames per frame (negative runs backwards) through a Hann window, linearly interpolated, and the op pushes the plain sum of all grains; performers manage headroom with `*` as everywhere else. Grain slots are a fixed pool of N allocated at compile time; a new grain takes a free slot or steals the oldest, so the audio thread never allocates. Table grains wrap around the table in both directions. Live grains are clamped so every frame they read is already written and not yet overwritten for the grain's whole life: the start is moved (and, if the rate is so far from 1x that no start fits, the grain is shortened) instead of letting a fast grain overtake the write head or a slow/reversed one fall off the tail.

Live-edit migration keeps grains sounding: a new grain op steals the old one's grain slots (the first min(N_old, N_new)), edge-detector state and, for `granulate`, the rolling buffer when its length is unchanged. Invalid arguments, a missing table, or zero grains compile to a zero-output op that still consumes its inputs, with a warning, per the forgiveness convention.
