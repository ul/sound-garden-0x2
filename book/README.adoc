= Writing the Sound Garden Book

The book lives next to the engine so every program in it runs against the current Sound Garden.
Source is AsciiDoc; the main output is a single HTML page with a player on every sound.
Rationale: link:../docs/adr/0005-book-toolchain.md[ADR 0005].

== Build

Needs `asciidoctor` (with Rouge), `ffmpeg` (with libmp3lame) and Rust.

[source,shell]
----
$ make -C book          # draft build with the sampler appendix, then open it
$ make -C book watch    # rebuild on save; reload the browser
$ make -C book check    # strict: any warning fails (unknown words, clipping, broken refs)
$ make -C book final    # without draft material
$ make -C book serve    # build and serve on http://localhost:8123
----

Output goes to `book/build/`: `index.html`, `theme/`, `media/` (renders) and `examples/` (every program as a file).
Open `index.html` directly, or serve the directory (`make serve`, or the `book` preview in `.claude/launch.json`).
Live editing only works when served: browsers don't load audio worklets from `file://`.

Renders are cached by a hash of the program, its render options and the `book_render` binary, so a rebuild only renders what changed, and changing the engine re-renders everything.
Unreferenced renders are deleted after each build.

== Layout

[horizontal]
`book.adoc`:: Title, attributes and the chapter list, in reading order.
`chapters/`:: One file per chapter: `01-<slug>.adoc`, each starting with a `==` heading. `sampler.adoc` shows every element the book uses and is included only in draft builds; keep it current when the theme or toolchain changes.
`examples/`:: Programs too long to live inline (pieces, studies), included into `[sound]` blocks.
`ext/sound_garden.rb`:: The Asciidoctor extension: `sg` highlighting and `[sound]` blocks.
`render/`:: `book_render`, which renders a program to audio and figures.
`theme/`:: Stylesheet, fonts and the player script.

== Sounds

A `[sound]` block is a listing that is also rendered and played:

[source,asciidoc]
------
.Tuning fork
[sound#tuning-fork, seconds=3, show="wave spectrum", from=0, to=0.01]
----
440 s \<1>
0.2 * \<2>
----
\<1> A sine wave at 440 Hz.
\<2> Scaled down to a fifth of full scale.
------

[horizontal]
`seconds`:: Render length; default 4.
`show`:: Figures under the player, any of `wave`, `spectrum`, `spectrogram`. The player always shows the whole clip.
`from`, `to`:: Waveform window in seconds. Under ~100 samples each sample is drawn as a lollipop.
`fscale`, `fmax`:: Spectrum axis: `log` (default) or `lin`, and its top frequency (default 20000). Use `lin` to show harmonic series.
`%loop`:: Loop playback (drones, rhythms).
`#id`:: Anchor for `<<id>>`; otherwise `sound-<chapter>-<n>`. Cross references read "Sound 3.2".

Sounds are numbered per chapter.
Callout markers are stripped before rendering, so annotated programs stay valid.
Each program is exported to `examples/<NN-chapter>/<nn-title>.txt`, linked from its `.txt` button; readers play it with `play_program < file`.
Include longer programs from files rather than pasting them: `include::../examples/piece.txt[]` inside the block.

Every render is checked: unknown words, compiler warnings and clipping are build warnings, and `make check` fails on them.
Programs with randomness pin a `seed:<N>` so the audio the reader hears matches the figure.

Readers can press *edit* on any sound to change the program and play it live with Cmd/Ctrl+Enter, through the browser engine in `build/live/` (see `sound_garden_web`).
Commits keep op state like the editor; *reset* returns to the printed program and its recording.

A listing that should not be played is `[source]` (the book's default language is `sg`), with the same highlighting and tooltips.

== Conventions

Structure and vocabulary: `docs/adr/0008-book-structure.md` and the Book section of `CONTEXT.md`.
The ladder of chapters and the way a chapter is made: `outline.adoc`.

* Each chapter grows one piece along its main line, opening with a short excerpt of the finished piece so the destination is in view.
* A piece is one program whose form unfolds from its own structure; its last listing is the full score.
* Voice is "we": author and reader exploring together.
* Maths is in the main text, introduced when the music needs it and built up from there.
* One sentence per line in the source, so diffs and review comments stay small.
* Levels: the reader hears the same loudness from chapter to chapter. Aim for peaks around 0.3–0.5 for sounds; pieces end with `limit`.
* Sample rate is 48,000 throughout.

=== Boxes

Example blocks with a role:

[horizontal]
`[.branch]`:: A branch: an optional side path (sound variation, derivation, history), folded under its title and a one-line summary. Nothing later depends on it.
`[.try]`:: An exercise, with its answer folded underneath; a sound answer is a playable `[sound]`.
`[.cutting]`:: Take a cutting: a named template the reader carries into later pieces.
`WARNING:`:: Only for ears and speakers.

=== Notation

Compatible with Puckette's _Theory and Technique of Electronic Music_ where possible.
Inline `stem:[...]`, display `[stem]` blocks (LaTeX, MathJax).

[horizontal]
stem:[R]:: sample rate (48,000)
stem:[n]:: sample index
stem:[t]:: time in seconds
stem:[f]:: frequency in Hz
stem:[A]:: amplitude
stem:[\varphi]:: phase, in radians
stem:[\omega = 2\pi f / R]:: angular frequency, radians per sample
stem:[x[n\]]:: a signal

Maths uses radians. Sound Garden's phases run over −1..1 per cycle; chapter 1 explains the mapping once, in a branch.

== Publishing

The `final` build is published with the playground and editor at ul.mantike.pro/sound-garden-0x2/book/ on every push to master.
A chapter goes into `book.adoc` unconditionally only when its piece is finished; until then it is included under `ifdef::draft[]`.
